# Решения

Решения с альтернативами, принятые по ходу работы (§12: неоднозначное — выбрать разумный
вариант, записать и продолжать).

## Фаза 0

### D-001. Версии инструментов

- **Решение:** TypeScript 6.0, Vite 8, Vitest 5, three.js r186, ESLint 10 + typescript-eslint 8.
- **Альтернатива:** TypeScript 7 (нативный компилятор). Отклонено: typescript-eslint
  поддерживает TS < 6.1.

### D-002. Playwright зафиксирован на 1.56.1

- В окружении предустановлен Chromium для этой версии, скачивание браузеров запрещено.

### D-003. WebGL2

- three.js начиная с r163 работает только с WebGL2. Поддержка WebGL2 на Android-устройствах
  аудитории — практически полная; отдельный WebGL1-путь не делаем.

### D-004. Шрифт

- **Решение:** Nunito (SIL OFL 1.1), вариативный, только подмножества latin и cyrillic
  (≈60 КБ), лежит в `src/assets/fonts`. Округлые формы соответствуют «мягкому» стилю.
- Турецкий (latin-ext, +35 КБ) добавим вместе с локализацией tr, если она понадобится.

### D-005. Язык

- Строго по брифу: `ru` → русский, всё остальное → английский. Таблица соответствия в
  `src/i18n/index.ts` (`RU_LANGS`); при желании туда можно добавить `be`, `kk`, `uz`.

### D-006. Слой платформы

- Интерфейс `Platform` + абстрактный `BasePlatform` с гарантиями, общими для Mock и Telegram:
  `ready` ровно один раз, нет двух `start`/`stop` подряд, кулдаун полноэкранной рекламы 60 с,
  пауза на время рекламы.
- Внешняя пауза — множество причин (`sdk`, `hidden`, `ad`): колбэки срабатывают только при
  переходе «нет причин ↔ есть причины», поэтому пауза SDK во время рекламы не «размораживает»
  игру раньше времени.

### D-007. Debug-режим

- Флаг `__DEBUG__` задаётся Vite через `define` (`true` в dev и в `--mode debug`, `false`
  в prod) и дополнительно требует `?debug=1`. Модуль `src/debug` подключается динамическим
  импортом под этим флагом, поэтому из prod-бандла вырезается целиком.
- e2e-тесты идут против dev-сервера (нужен debug-API); отдельная проверка prod-сборки через
  sdk-dev-proxy — в фазе 6.

### D-008. Масштаб UI

- Базовый `font-size` корня = короткая сторона / 30, в пределах 12–20 px; весь UI в `rem`.
  Минимальная тач-цель — `max(44px, 3rem)`.

### D-009. Скриншоты в репозитории

- Полные PNG (≈1 МБ на ориентацию) в git не кладём: они в `artifacts/` (в .gitignore).
  Для истории в `docs/progress/phase-N.jpg` сохраняется сводный лист
  (`tools/contact-sheet.ts`).

### D-010. Идентификаторы наборов

- Короткие префиксы из Приложения А: `food`, `home`, `nat`, `pet`, `sea`, `tr`, `toy`, `ws`,
  `fx`, `sp`; обучение — `tut`, отладочный набор — `test`.
- «Еда» открыта сразу вместе с обучением (в обучении 5 уровней, правило «7 решённых» к нему
  неприменимо).

## Фаза 1

### D-011. Знание о ячейке — множество допустимых классов

- Состояние ячейки в решателе — битовая маска допустимых классов: бит 0 — «пусто», бит c —
  «куб класса c». В classic это ровно `UNKNOWN = 0b11`, `KEEP = 0b10`, `BREAK = 0b01`.
- Для Round 2 (dual) то же представление расширяется до трёх бит без смены движка
  пропагации; решатель линии подключается по `ruleset` (`lineSolverFor`).

### D-012. Кэш масок и длина линии

- Маски строятся лениво для каждой длины n и раскладываются по корзинам (count, тип группы).
  Поддерживаются линии до 24 (2^24 масок) — жёсткого лимита 10 в движке нет, 15 проверено
  тестом. Более длинные линии дают понятную ошибку.

### D-013. Два режима пропагации

- **Обычный** (по умолчанию): выводы применяются сразу — быстро, используется для проверки
  решаемости, прореживания, бота.
- **Послойный** (`layered`): линии раунда смотрят на снимок начала раунда. Число раундов —
  «глубина» рассуждений, а «раунд с одной продвинувшейся линией» — настоящее узкое место.
  Используется для метрик сложности. Оба режима дают одну и ту же неподвижную точку.

### D-014. Прореживание

- Типы из `hideFirst` (кружки/квадраты в ранних наборах) пробуем скрыть все, без учёта
  целевой доли; затем общий проход до целевой доли. Если скрыть не удалось, сборка печатает
  предупреждение (`remainingFirst`).
- Расписание долей: food 0,20 → sp 0,50; `hideFirst`: food — кружки и квадраты,
  home — только квадраты (кружки вводятся с набора 2, квадраты — с набора 3).
- Обучение: целевая доля 0; уровни 1–4 без кружков/квадратов, в 5-м они видимы.

### D-015. Оценка сложности (стартовая)

- `score = раунды + 1,5·узкие места + 20·доля скрытых + 12·(кружки + 1,5·квадраты) + 2·log2(клеток)`,
  пороги 12/22/34/48 → сложность 1–5.
- `targetTime = 1,1 с × ударов + 4 с × раундов + 6 с × узких мест`, округление до 10 с, не меньше 30.
- Коэффициенты калибруются прогонами бота в фазе 4. Для обучения сложность задана вручную (1).

### D-016. Уточнения правил

- Треснувший куб навсегда помечен: кисть его не снимает (иначе можно получить второй штраф
  за тот же куб).
- Звёзды считаются по всем промахам попытки (`totalMistakes`): «Продолжить за рекламу»
  уменьшает текущий счётчик, но не возвращает звезду.
- Протяжка молотком, начатая на помеченном кубе, даёт «бонк» и продолжается дальше;
  кубы, скрытые срезом, протяжкой пропускаются.

### D-017. Подсказка

- Достоверное знание — только сломанные и треснувшие кубы; пометки игрока могут быть
  ошибочными. Ищется линия с наибольшим числом полезных действий; ошибочно помеченный куб,
  который нужно сломать, подсказка сначала «снимает».

### D-018. Формат наборов

- В `public/levels/<pack>.json` — по уровню на строку (удобные диффы), `index.json` — список
  наборов и уровней для меню. Отладочный набор `test` помечен `debugOnly`.
- Фигуры обучения — в `content/shapes/*.ts` (DSL + помощник `fromLayers` для ASCII-слоёв).

## Фаза 2

### D-019. Шейдер кубов — свой `ShaderMaterial`

- Вместо `onBeforeCompile` к Lambert — свой материал с тем же освещением «полусфера +
  направленный свет», посчитанным в шейдере. Проще контролировать фаску, глифы и флаги.
- `ColorManagement` выключен, вывод без преобразования: цвета задаются в sRGB «как есть»
  и совпадают с CSS-палитрой UI.

### D-020. Глифы на гранях

- UV грани считаются в шейдере из локальной позиции, а не из UV `BoxGeometry`. Глифы на ±X/±Z
  стоят вертикально, на ±Y поворачиваются к камере шагом 90° (uniform `uTopBasis` из азимута).
- Выборка атласа — `textureGrad` с производными от позиции в пространстве блока: они
  непрерывны между соседними кубами, поэтому на швах нет артефактов мип-уровней.
- Атлас 1024², ячейки 128 px, 64 слота: 45 статических (пусто, 0–15, кружки 2–15, квадраты
  3–15, трещина) и динамические слоты под цветные/двойные числа Round 2.

### D-021. Фаска и швы

- Нормаль «скруглённого куба» у рёбер (радиус 0,07) + затемнение к краю грани. Геометрия —
  обычный `BoxGeometry` (12 треугольников на куб).

### D-022. Состояние инстансов

- Сломанные и скрытые срезом кубы схлопываются в вершинном шейдере по флагу `aState` —
  матрицы не переписываются. Волна окраски — задержка в `aReveal` + общий uniform времени,
  без обновления буферов в кадре.

### D-023. Тач-ввод

- Касание куба применяет инструмент не сразу, а через 110 мс или после сдвига на 7 px (либо
  по отпусканию): за это время второй палец успевает начать pinch, и куб не ломается случайно.

### D-024. Фиксация оси протяжки

- Ось фиксируется по экранному направлению движения (сдвиг ≥ 14 px), выбирается ось,
  проекция которой лучше совпадает с движением. Смещение вдоль линии — ближайшая к лучу
  указателя точка прямой (при оси «в глубину» — по экранной проекции).
- Вариант «по соседнему кубу под курсором (DDA)» отклонён: после удара по стартовому кубу
  под курсором оказывается куб за ним, и ось случайно фиксировалась бы вглубь.

### D-025. Срезы

- Срез по X/Z идёт со стороны, обращённой к камере (сторона фиксируется, пока срез активен),
  по Y — всегда сверху.
- Ручки: X и Z — у нижних видимых рёбер, Y — у левого вертикального; в покое ручка чуть
  вынесена за конец ребра, ручки не накладываются (разведение в экранных координатах) и не
  выходят за экран. Дублируются кнопками «ось / − / +» и клавишами R/Q/E.

### D-026. Кадрирование

- Точный расчёт: 8 углов блока при ракурсах по умолчанию (азимут 35° и 45°) вписываются
  в свободную от HUD область с полями под ручки срезов (слева и снизу, в пикселях); центр
  проекции сдвигается через `setViewOffset`. Зум пользователя — множитель к этому расстоянию.
- Ландшафт телефона: инструменты — правой колонкой, срезы — левой, время — рядом с паузой,
  блок занимает всю высоту.

### D-027. Рендер по требованию и время

- `requestAnimationFrame` только после `invalidate()` или пока идут анимации; шаг времени
  анимаций ограничен 100 мс.
- Таймер уровня — отдельный интервал 250 мс; стоит на паузе, при внешней паузе (SDK,
  скрытая вкладка, реклама) и после окончания уровня.

### D-028. Итог уровня

- Итог — «шторка» снизу (в ландшафте — справа), а не модальное окно: ожившая фигура
  остаётся видна, камера перекадрируется в свободную часть. При победе срез сбрасывается.

### D-029. Среда тестов

- В контейнере нет GPU: Chromium рендерит через SwiftShader, поэтому FPS в debug-панели
  здесь не показателен (4–30). e2e ждут условий, а не фиксированных пауз. Проверка FPS на
  реальных устройствах — фаза 7.

### D-030. Целые значения в шейдере — flat-varying

- Флаги `aState` и индексы глифов передаются во фрагментный шейдер как `flat` varying и
  дополнительно округляются. Интерполяция превращала 6.0 в 5.9999995, и бит «помечен»
  мигал по пикселям (шум на помеченном треснувшем кубе).

### D-031. Автономная сборка для просмотра

- `npm run release:preview` собирает `artifacts/release/cube-sculptor.html`: весь JS, CSS,
  шрифты и уровни внутри одного файла, открывается двойным кликом без сервера (с `file://`
  браузеры не загружают модульные скрипты и не выполняют `fetch`). Режим сборки `standalone`
  включает отладочный набор «Тест 10×10×10» и `?debug=1`. Рядом в архиве лежит `build.zip`
  для Telegram Mini App.

## Фаза 3 (подготовка пайплайна)

### D-032. Заполнение вокселей

- Выборки 4×4×4 на ячейку; «внутри» — по чётности пересечений луча с мешем вдоль каждой из
  трёх осей, точка внутри, если так считают ≥ 2 оси (дырявый меш почти не влияет: тест с −8 %
  треугольников). Лучи строятся растеризацией треугольников по сетке выборок, со сдвигом от
  рёбер и вершин.
- Длинная сторона = `maxSize`, ячейки кубические; тонкая ось растягивается до 2 ячеек.
  Модель центрируется, пустые крайние слои обрезаются — итоговая сетка может быть меньше
  `maxSize`.

### D-033. Цвет вокселей

- Для каждой открытой грани поверхностной ячейки — 5 выборок в ближайших точках меша (UV +
  барицентрики), каждая приводится к палитре игры (OKLab), цвет ячейки — голосование. Так
  сохраняются чёткие цветовые зоны вместо «грязного» среднего. Внутренние ячейки получают
  цвет ближайшей поверхностной (BFS).
- Не больше 6 цветов: самый редкий цвет сливается с ближайшим оставшимся.
- Выборка текстуры: UV повторяются, но соседние тексели у краёв зажимаются (иначе у полюсов
  подмешивается противоположный край атласа).
- Палитра игры — 33 цвета (`tools/voxel/palette.ts`).

### D-034. Ручные правки и сборка

- Правки `add`/`remove` из manifest — в координатах итоговой (обрезанной) сетки, той, что на
  миниатюрах ревью.
- Уровни без вокселей сборка пропускает: в manifest сразу внесены все 100 объектов
  Приложения А и резерв А.4.
- Сетки наборов: первые 5 уровней — нижняя граница диапазона из Приложения А.2, остальные —
  верхняя (food 5→6, nat 6→7, sea 7→8, toy 8→9, fx 9→10).

### D-035. Текстуры GLB

- PNG/JPEG декодируются на чистом JS (pngjs, jpeg-js). Если Meshy отдаст WebP/KTX2 — добавим
  декодирование через Chromium.

### Открытый вопрос: хранение исходных GLB

- Пилотные GLB (3 шт., единицы МБ) кладём в git. Для 100 моделей (200–500 МБ) предлагаю
  Git LFS или хранить только воксели и оптимизированные модели раскрытия; решает владелец.

## Фаза 3 (пилот)

### D-036. Модель и параметры Meshy

- **Решение:** `ai_model: "latest"` (Meshy 6) для preview и refine, параметры —
  `PREVIEW_PARAMS`/`REFINE_PARAMS` без изменений. 30 кредитов на объект (20 + 10), задача
  выполняется за 1–2 мин.
- **Альтернатива:** meshy-5 (5 + 10 кредитов). Не пробовали: фигуры Meshy 6 и так чистые, а
  узкое место пилота — не качество меша, а малая сетка (D-038).
- `remove_lighting: true` блики убирает не полностью (у яблока белые пятна) — на воксели не
  влияет: цвет ячейки выбирается голосованием (D-033).

### D-037. Превью Meshy рендерим сами

- Meshy MCP не отдаёт ссылку на свою миниатюру. `npm run meshy:preview` рендерит GLB
  (three.js `GLTFLoader` в headless Chromium, вид 3/4 спереди, белый фон) в
  `content/meshy/raw/<id>.png` — его подхватывает `npm run thumbs`.
- **Альтернатива:** скачивать `thumbnail_url` через REST API Meshy. Отклонено: нужен
  API-ключ вне MCP.

### D-038. Правки могут расширять сетку

- На сетках 4–8 тонкие детали (черешок, лист, уши, киль, крылья) не набирают порог заполнения
  и пропадают. Снижение порога до 0,25 их не возвращает, а тело становится угловатым.
- **Решение:** `edits.add` за пределами итоговой сетки (в том числе с отрицательными
  координатами) расширяет её; `remove` применяется в исходных координатах. Так деталь
  ставится там, где её срезала вокселизация.
- Итог пилота: все три фигуры потребовали ручных правок (2–10 коробок). Для фазы 4 закладываем
  ~10 мин ревью и правок на объект.

### D-039. Палитра фигуры

- Затенение в текстуре раскалывает одну заливку на соседние цвета палитры (кот: пятна
  `#d9772f` и `#e0604a`).
- **Решение:** `source.palette` — подмножество палитры игры, к которому приводятся цвета
  фигуры; цвета правок `add` берутся из него же.
- **Альтернатива:** глобально сливать близкие цвета в `reduceColors`. Отклонено: сольются и
  намеренно разные оттенки в других фигурах.

### D-040. Запись в manifest

- `tools/meshy-record.ts` форматирует manifest Prettier'ом — иначе `JSON.stringify` разворачивает
  все массивы и diff каждой записи — на весь файл.
- На вход Prettier подаётся JSON с отступами: объекты остаются развёрнутыми, массивы чисел
  сворачиваются. (Первая версия подавала сжатый JSON — Prettier сворачивал все короткие
  объекты в строку; исправлено в начале фазы 4.) Правки `edits` в manifest — тоже развёрнутые
  объекты, чтобы запись их не трогала.

## Фаза 4 (начало)

### D-041. Без кнопки «Держите — кисть»

- **Решение (владелец):** кнопку убрали из HUD — рядом есть переключатель «Молоток / Кисть»,
  а назначение круглой кнопки без подписи было неочевидно. Отход от брифа (раздел
  «Мобильные»).
- Временная кисть осталась на ПК: ПКМ и удержание `Space`. Нижняя панель — сетка
  «срезы | инструменты | пусто», переключатель по центру; в ландшафте телефона — справа.

### D-042. Модель Meshy для массовой генерации — meshy-6

- Сравнение (30 кредитов): кот `pet_01` по тому же промту и новый гриб `food_02` на meshy-5
  (5 + 10 кредитов за объект против 20 + 10).
- meshy-5 хуже держит промт: кот с чёрными лапами и тонким поднятым хвостом вместо «хвост
  вокруг лап», гриб с длинной тонкой ножкой вместо «пухлый, толстая короткая ножка».
  Тонкие части пропадают в вокселях: кот без правок — 21 куб против 33 у meshy-6, гриб —
  9 кубов («Т»). Экономия вдвое уходит на ручные правки и перегенерации.
- **Решение:** остаёмся на meshy-6 (`PREVIEW_PARAMS`/`REFINE_PARAMS`). Лист сравнения —
  `docs/progress/meshy5-compare.png`. GLB гриба meshy-5 оставлен для учёта, уровень из него
  не собирается (нет вокселей) — до перегенерации на meshy-6.

### D-043. Тонкие оболочки: `source.shell`

- Абажур, зонт, лейка, стенки кружки смоделированы оболочками без объёма (или тоньше ячейки):
  чётность лучей их не видит, сетка выходит пустой даже при пороге 0,15.
- **Решение:** `source.shell: true` — выборки, через которые проходит поверхность, тоже
  заполнены (точки треугольника с шагом ≤ половины выборки). Опция включается на уровне,
  поэтому уже настроенные фигуры не меняются. Обычно вместе с порогом 0,25.
- **Альтернатива:** всегда добавлять поверхность. Отклонено: сплошные фигуры «толстеют» на
  границе и сбиваются правки пилота.

### D-044. Правка `paint`

- `edits.paint` перекрашивает только заполненные кубы коробки (после `add`); `add` заливает
  коробку целиком, включая пустые ячейки. Нужна для слоёв бургера, полосы кружки,
  циферблата, косточек арбуза. Порядок правок: `remove` → `add` → `paint`.

### D-045. Узкие фигуры первых уровней «Еды»

- Морковка и мороженое на сетке 5 выходят шириной в 2 клетки и не читаются. Для них
  `maxSize: 6` (верхняя граница набора) — отход от D-034 для двух уровней.
- Гриб `food_02` на meshy-5 оставлен по решению владельца (порог 0,15 — шляпка и ножка).

### D-046. Вокселизация партиями

- `npm run voxelize` не останавливается на неудачной фигуре: пишет ошибку, продолжает и
  завершается с кодом 1.
- Партия из 15 объектов: 11 из 16 фигур потребовали правок (перекраска, досборка деталей,
  `shell`), 4 — только палитру или порог. Узкие и полые предметы — основной источник работы.

### D-047. Фигуры из MagicaVoxel

- **Решение (владелец):** объект Приложения А можно нарисовать вручную в MagicaVoxel —
  `source.kind: 'vox'`, файл `content/vox/<id>.vox`, импорт `npm run vox` в тот же формат
  `content/voxels/<id>.json`, что и у Meshy. Первый — `home_09` «Домик» (0 кредитов).
- Свой читатель и писатель `.vox` (SIZE/XYZI/RGBA; узлы сцены, материалы и слои
  пропускаются) — формат открытый, зависимость не нужна. Проверен на всех примерах
  MagicaVoxel 0.99.7 (версия файла 200). Файл с несколькими моделями — ошибка.
- Оси: Z MagicaVoxel → Y игры, сторона Y = 0 (к камере по умолчанию) → перед (+Z).
- Цвета приводятся к палитре игры (ближайший в OKLab, ≤ 6); палитра игры для MagicaVoxel —
  `npm run vox -- palette` → `content/vox/cube-sculptor.png`.

### D-048. Фигуры «Дома» и «Природы» в MagicaVoxel

- `home_08`, `home_10`, `nat_01`–`nat_10` нарисованы вручную: DSL проекта (`box`, `cylinder`,
  `ellipsoid`, профили) → `.vox` с палитрой игры; дальше — обычный `npm run vox`. Исходник
  фигуры — сам `.vox` (правится в MagicaVoxel), генератор не хранится.
- Размеры — по сеткам наборов (D-034): «Дом» до 6, «Природа» 6 и 7.
- Радуга (`nat_07`): в ширину 7 помещаются только три полосы — красная, жёлтая, синяя
  (порядок радуги сохранён, оранжевая и зелёная опущены).
- Снеговик: глаза убраны — рядом с шляпой они давали чёрную «маску пингвина»; пуговицы
  разнесены через слой.

### D-049. Остальные наборы в MagicaVoxel

- **Решение (владелец):** все оставшиеся 68 объектов нарисованы в MagicaVoxel, как в D-048;
  Meshy больше не используется. Итог: 19 фигур из Meshy, 81 — из MagicaVoxel.
- Сетки — по слотам (D-034): питомцы 7, море 7–8, транспорт 8, игрушки 8–9, мастерская 9,
  сказки 9–10, космос 10.
- Животные, транспорт и инструменты, которые узнаются по силуэту сбоку (свинка, утка, кит,
  рыбка, конёк, акула, дельфин, машины, паровоз, труба, лошадка-качалка), нарисованы
  профилем, повёрнутым к игроку.
- Молоток и гаечный ключ в Приложении А «лежат», но нарисованы стоя: лёжа они видны с
  ребра и не узнаются.
- После ревью переделаны: свинка (явный профиль, глаза), краб (клешни-крючки), морской конёк
  (корона, кольца, завиток), подлодка (корпус-труба), воздушный шар (клинья вместо клеток),
  топор (крупное лезвие), корона (явные зубцы), планета (крупнее, кольцо шире), колба (узкое
  горлышко).

## Фаза 5

### D-050. Прогресс и открытие уровней

- Прогресс — в сохранении платформы под ключом `progress`:
  `{ v: 1, levels: { id: [звёзды, лучшее время, меньше всего промахов] } }`. Остальные ключи
  сохранения не трогаются (в фазе 6 туда лягут настройки и попытки). Битые записи
  пропускаются.
- Сохраняем на каждой победе с `flush` — это логическая точка (§8), побед немного.
- Открытие (§4): набор — первый в цепочке или `unlockAfter` решённых в предыдущем (`tut` и
  «Еда» — `unlockAfter: 0`, открыты сразу); уровень — первый, уже решён или решён
  предыдущий. Отладочные наборы вне цепочки и открыты всегда; debug-API открывает любой
  уровень в обход замков.

### D-051. Коллекция

- Миниатюры рисуются в игре тем же рендером (`FigureStudio`: `Renderer` + `BlockView` в
  состоянии «раскрыто», без пустых кубов и подсказок) во втором WebGL-контексте на скрытом
  холсте, по одной за кадр, и кешируются на сессию. После снимков контекст освобождается.
- **Альтернатива:** готовые PNG в сборке. Отклонено: +2 МБ к архиву и рассинхрон с рендером
  при правках фигур.
- Нерешённые — одинаковая плашка «?», а не силуэт фигуры: силуэт подсказывал бы форму
  головоломки.
- Просмотр — отдельный `FigureStudio` в модальном окне с поворотным столом и медленным
  вращением; закрытие любым путём (кнопка, Escape) освобождает контекст.

### D-052. Сохранение настроек

- Весь блоб сохранения держит `SaveStore` (`src/app/save.ts`); прогресс (`progress`) и
  настройки (`settings`) пишут свои разделы через него, чужие ключи сохраняются как есть.
- Настройки пишутся без `flush` на каждое изменение (платформа сама копит), прогресс — с
  `flush` на победе (D-050).
- При загрузке из настроек берутся только известные булевы ключи; остальное — по умолчанию.

### D-053. Звук и музыка процедурные

- SFX синтезируются в Web Audio по §9: тон и шум с огибающими, случайная вариация высоты,
  минимальный интервал на тип (протяжка по 10 кубам не превращается в треск).
- Музыка — генеративная петля в том же движке (аккорды Cmaj7–Am7–Fmaj7–G6, бас, пентатоника,
  68 уд/мин), планировщик с упреждением. **Альтернатива** по брифу — OGG-лупы CC0 или от
  владельца; своих файлов пока нет, а генеративная петля ничего не весит. Если владелец даст
  лупы, заменим `MusicLoop` на проигрывание буфера, интерфейс `Sound` не меняется.
- `AudioContext` создаётся по первому жесту; на `pause` платформы (реклама, скрытие
  вкладки) — `suspend`, на `resume` — продолжение. Громкость — две шины (музыка и звуки),
  сейчас управляются переключателями настроек.

### D-054. Обучение: сценарии шагов и рука-указатель

- Сценарий — список шагов на уровень (`src/ui/hud/Tutorial.ts`): строка текста, цель руки
  (грань куба по условию на подсказку, либо элемент интерфейса) и события, по которым шаг
  засчитан.
- Грань под рукой выбирается среди видимых и повёрнутых к камере (не ребром); при повороте
  камеры цель пересчитывается. Проекция — каждый кадр после рендера.
- Шаги засчитываются по действиям, а не по «Далее»: обучение не мешает играть и не
  блокирует ввод. Решённый уровень обучения при повторе показывается без подсказок.

### D-055. Реквизит и фон меню процедурные

- Молоток и кисть (Приложение А.3, `prop_hammer`, `prop_brush`) — процедурные модели из
  цилиндров и бокса, поверх блока без теста глубины, короткий взмах к кубу и затухание.
  Генерация в Meshy не нужна: модели крошечные на экране, детали не читаются, а
  процедурные не весят ничего.
- Фон меню — запасной вариант из Приложения А.3: градиент и парящие кубы на canvas 2D (не
  второй WebGL-контекст). `env_workshop` не делаем.
